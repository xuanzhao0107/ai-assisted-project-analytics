# Project Selection

## Objective

The objective of this stage was to identify a real-world project that could support an AI-assisted project analytics portfolio.

The selected project needed to:

- provide reliable and publicly available project data;
- support progressive Excel learning;
- enable meaningful project management analysis;
- support future development using SQL, Power BI and Python;
- demonstrate practical PM, PMO and data analytics skills.

## AI-Assisted Research Process

AI was used as a research assistant to identify and compare potential real-world projects.

The research process consisted of two stages:

1. Project discovery
2. Critical reassessment and source verification

Rather than accepting the initial AI recommendation, the shortlisted projects were reassessed using a weighted decision framework.

## Shortlisted Projects

Three projects were shortlisted:

- Cross River Rail
- Suburban Rail Loop East
- Inland Rail

## Evaluation Framework

The projects were evaluated using the following criteria:

| Criterion | Weight |
|---|---:|
| Official & quantitative data availability | 25% |
| Excel learning suitability | 20% |
| Project management analytical value | 20% |
| Dashboard potential | 15% |
| Future SQL / Power BI / Python scalability | 10% |
| Career & portfolio storytelling value | 10% |

## AI-Assisted Evaluation Result

| Project | Weighted Score |
|---|---:|
| Cross River Rail | 4.90 / 5 |
| Suburban Rail Loop East | 3.85 / 5 |
| Inland Rail | 3.75 / 5 |

## Final Selection

**Cross River Rail (CRR)** was selected as the core project for this portfolio.

CRR provides a strong combination of:

- publicly available government and audit data;
- historical budget revisions;
- schedule changes;
- multiple major work packages;
- project delivery and funding information;
- clear opportunities for Excel-based project controls analysis.

It also provides sufficient complexity for future extensions using SQL, Power BI and Python.

## Human Validation of AI Output

AI-generated recommendations were treated as research hypotheses rather than verified facts.

Official sources were checked before accepting the recommendation.

During validation, several AI-proposed dataset fields, including change-specific cost impact, schedule impact in days and standardised risk severity levels, could not yet be confirmed as consistently available across official project change reports.

These fields will therefore not be assumed to exist unless they can be verified during the data collection stage.

This validation step demonstrates a human-in-the-loop approach in which AI supports research and idea generation while final analytical decisions remain evidence-based.
